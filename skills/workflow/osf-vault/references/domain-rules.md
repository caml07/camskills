# OSF Domain Rules

Use this reference when a note request touches Entities or lore relationships.

## Episode vs Entity

An **Episode** is the numbered YouTube release. An **Entity** is an in-universe
concept. They remain separate even when they share a title.

Example:

- `[[OSF 053 - Terminal]]` — Episode
- `[[Terminal]]` — Entity

## Entity creation threshold

Create or promote an Entity when at least one condition is true:

1. source material explicitly establishes it as a place, organization, system,
   phenomenon, or person;
2. it appears in more than one Episode;
3. another Episode explicitly references it;
4. it is the primary subject/location of an Episode;
5. the user explicitly decides it deserves its own node.

Do not create Entities for every capitalized noun or visually suggestive phrase.

## Aliases

Add an alias only when identity is clear. Exact canonical names are safest.
Generic phrases such as `the Monolith` should not silently resolve to a specific
Entity unless evidence makes the identity unambiguous.

## Relationship certainty

- **confirmed** — source evidence explicitly supports the relationship.
- **inferred** — interpretation is plausible but not explicit canon.
- **candidate** — detected/suggested and awaiting review.
- **rejected** — reviewed and declined; retain the decision.
- **reopened** — a rejected/settled decision returned to review because new
  evidence or the user's interpretation changed.

Do not upgrade confidence merely because two notes use similar vocabulary.

## Personal interpretation

The user's opinion is evidence of **their interpretation**, not evidence of OSF
canon. Preserve it faithfully and link the relevant canon notes so both layers
remain useful without being conflated.
